# adiabatic-confinement-billiard

Code repository accompanying the publication entitled "Adiabatic confinement and escape in an open billiard" by M. R. Sales, L. C. de Souza, R. L. Viana, E. D. Leonel, and I. L. Caldas.

This project contains the code to generate and plot the data from all figures. Please keep in mind that some simulations take several days to finish.

## The model

The billiard is the open channel

$$|y| \le h(x) = \frac{h_0}{1 + (x/L)^2}, \qquad |x| \le x_m,$$

where $h_0$ is the half-width at the centre and $L$ is the profile length. The segments $x = \pm x_m$ are apertures, so a particle that reaches one of them escapes. All simulations use $h_0 = 1$, $x_m = 10$, and unit speed, and the initial conditions lie on the Poincaré section $x = 0$, $v_x > 0$, parametrized by $(y, v_y)$.

## Requirements

### Compiler and build system

- A C compiler supporting C17, tested with GCC, Apple Clang, and Intel oneAPI `icx`
- GNU Make
- OpenMP (used by `basin` and `uncertainty`)

On Linux (Debian/Ubuntu):

```bash
sudo apt install build-essential
```

On macOS, Apple Clang requires `libomp` for OpenMP:

```bash
brew install libomp
```

Windows is not supported natively. Windows users can run the code using the Windows Subsystem for Linux (WSL2) or a Linux virtual machine.

### Python

- Python 3.9+
- The packages listed in `requirements.txt`, which include [pynamicalsys](https://pynamicalsys.readthedocs.io) for the plot style

```bash
pip install -r requirements.txt
```

## Building

From the root of the repository, run

```bash
make
```

to compile every program in `experiments/`. The executables are placed in `build/bin/`. To compile a single program, use its name:

```bash
make escape
```

The compiler can be selected with `CC`, and OpenMP can be disabled with `USE_OMP=0` (the parallel programs then run on a single thread):

```bash
make CC=icx
make CC=clang
make USE_OMP=0
```

Link-time optimization (`-flto`, or `-ipo` with `icx`) and `-O3` are enabled by default. To remove the build files, run `make clean`.

## Running the programs

All programs must be executed from the root of the repository. They write their output to `data/`, which is created automatically. The arguments are passed as `--name value` pairs in any order, and running a program with `--help` lists the required and optional arguments. For example,

```text
$ ./build/bin/escape.x --help
usage: ./build/bin/escape.x --L <float> --nic <int> --nmax <int> [options]

required:
  --L <float>   profile length
  --nic <int>   number of initial conditions
  --nmax <int>  maximum number of collisions

optional:
  --h0 <float>  half-width at the centre, default = 1.00000
  --xm <float>  position of the apertures, default = 10.00000
```

and

```bash
./build/bin/escape.x --L 5 --nic 100000 --nmax 100000
```

computes the escape collision number of $10^5$ initial conditions for $L = 5$ and writes them to `data/escape_h0=1.00000_L=5.00000_xm=10.00000_nic=100000_nmax=100000.dat`. The format of the output file of each program is described at the top of its source file in `experiments/`.

The programs `basin` and `uncertainty` run in parallel and accept `--nthreads` to set the number of OpenMP threads. By default, they use all available threads.

## Reproducing the figures

The data of each figure are generated by the scripts in `runners/`. Each script compiles the program it needs and runs it with the parameters used in the paper:

| Figure   | Script                          | Program       |
| -------- | ------------------------------- | ------------- |
| 1, 2     | none (computed in the notebook) |               |
| 3(a)-(c) | `runners/fig3abc.py`            | `collisions`  |
| 3(d)     | `runners/fig3d.py`              | `action`      |
| 4        | `runners/fig4.py`               | `section`     |
| 5, 6, 7  | `runners/fig5_6_7.py`           | `escape`      |
| 8        | `runners/fig8.py`               | `basin`       |
| 9        | `runners/fig9.py`               | `uncertainty` |

For example,

```bash
python runners/fig4.py
```

All scripts accept the following options:

- `--cc`: the C compiler (default: `gcc`)
- `--jobs`: the number of runs executed simultaneously (default: 1)
- `--dry-run`: print the commands without running them
- `--nthreads`: the number of OpenMP threads per run (`fig8.py` and `fig9.py` only; default: all available)

For instance, `python runners/fig5_6_7.py --cc clang --jobs 10` runs ten values of $L$ at a time. The output of each run is written to `logs/`. Use `--dry-run` to see the exact commands, which can also be executed directly, for example on an HPC cluster:

```text
$ python runners/fig3abc.py --dry-run
./build/bin/collisions.x --L 10.0 --y0 0.0 --vy0 0.707107 --nmax 1000 --h0 1.0 --xm 10.0
./build/bin/collisions.x --L 10.0 --y0 0.0 --vy0 0.469472 --nmax 1000 --h0 1.0 --xm 10.0
./build/bin/collisions.x --L 2.0 --y0 0.0 --vy0 0.707107 --nmax 1000 --h0 1.0 --xm 10.0
```

> **_NOTE_**: The data of Figs. 3 and 4 take a few minutes to generate. The data of Figs. 5 to 9 are computationally expensive: $10^6$ initial conditions evolved for up to $10^6$ collisions for each of the 20 values of $L$ (Figs. 5 to 7), $10^6$ grid points evolved for up to $10^6$ collisions for each of the 6 values of $L$ (Fig. 8), and 10 realizations of $10^4$ pairs for each of the 100 values of $\varepsilon$ and 11 values of $L$ (Fig. 9). Individual runs can take several days, so we recommend running them on an HPC cluster.

Once the data are generated, run the cells under the heading of each figure in `Plots.ipynb`. All figures are saved in `figures/`. The cells under `Figs. 5, 6 and 7` read the escape data once, so run them before the cells of each of these figures.
